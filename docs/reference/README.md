# The copilot's knowledge base

Everything in this folder is what the copilot retrieves from, and nothing outside it is: plans,
history and contributor notes live beside it (`docs/README.md`). Each file starts with front
matter (title, scope, module, last_verified) - the contract is in `docs/README.md`.

| Folder | What it covers |
|---|---|
| `factory/` | the cell as a whole: ground truth, hardware model, factory vs twin, the production cycle, alarm codes, upgrades, validation, common questions |
| `machines/` | one document per module and mechanism: warehouse, gripper robot, oven, sorting line, controller board, edge computer, running gear, components |
| `twin/` | the 3D twin: its overview, the 3D view and each side panel (`twin/panels/`) |
| `dashboard/` | one document per dashboard page - generated from `web/src/dashboard/guide.ts` by `web/scripts/guide-md.ts`; edit the guide, not the files |
| `guide/` | the user guide, and the full dashboard guide (generated, not indexed) |
| `plc/` | the PLC program, generated from the program the twin runs by `docs/gen/plc_docs.py` |
| `maintenance/` | preventive and predictive maintenance, and maintenance at the edge |
| `vision/`, `process/` | vision QC; the bake as a process (generated by `stf-cad/hbw/bake.py`) |
| `copilot/` | how a question is answered, answer settings, the speech pipeline |
| `operations/` | deploying, staging, the database, photo intake, security |
| `architecture/` | the agent graph, the RAG design, error codes, devices, electrics, the simulation engine |

How the chat uses them:

- The chat runs on the server. The language model calls the twin's tools
  (`services/api/agent/tools.py`): machine health, alarms, the month, OEE, energy, carbon, the
  scheduler, vision, security, the running twin's live state, this page's guide, and
  `search_docs` - hybrid BM25 and vector search over the passages of these documents
  (`web/public/copilot/kb.json`), judged and corrected by `services/api/rag/crag.py`.
- `page_guide` returns `dashboard/<page>.md` for the page the user is on.
- Live numbers come from the tools at question time; these documents explain what the numbers
  mean and where they come from. Every answer's numbers and claims are checked against what it
  was given (`services/api/agent/verify.py`, `claims.py`).

Rebuild after editing: `make copilot` (`make guide` first for the dashboard pages), then
`make db-seed-kb` for a deployed vector store.

Everything in the twin is simulated from engineering models; nothing is measured on a physical
machine.
