# STF digital twin: handoff for building the complete CAD in FreeCAD via the FreeCAD MCP

Generated by `stf-cad/hbw/make_handoff.py` on the date in the footer. Sections 1-9 are
written; the appendices (A-G) are dumped live from the Python models, so they are
exactly what the current generators build. **Re-run `python3 make_handoff.py` after any
model change.**

## 0. What to do in this session

Build the fischertechnik **Fabrik Simulation 24V (536634)** as a precise, coloured,
articulated FreeCAD model **inside a running FreeCAD, through the FreeCAD MCP**
(`mcp__freecad__run_script` / `mcp__freecad__send_command`). The Python parameter tables
in `~/workspace/stf-cad/hbw/` are the single source of truth: **generate** geometry from
them, never retype numbers.

Preconditions:
1. FreeCAD 1.1.3 GUI is running with the MCP add-on's RPC server started (Workbench
   "MCP Addon" -> Start RPC Server). If `run_script` returns "Connection refused", the
   server is not running; ask the user to start it.
2. First call: `run_script` with
   `import sys; sys.path.insert(0, '/Users/sohampatel/workspace/stf-cad/hbw')`,
   then `import hbw_model, vgr_model, oven_model, sorting_model, plc_model, factory_layout, detail`.
   After that you can build inside the live GUI document with the same code the headless
   builder uses (`stf_freecad.py`: container() / solid() / shape(); `detail.precise()`
   gives the chamfered/threaded/spring B-rep).
3. Advantage over headless: ViewObjects exist in the GUI, so set `ShapeColor`,
   `Transparency` and visibility directly. No `fcstd_colour.py` zip patching is needed.

Suggested order (verify each step before the next; take a view screenshot with
`FreeCADGui.ActiveDocument.ActiveView.saveImage(path, 1600, 1000, 'White')` and look at it):
1. Run every proof headless first (commands in section 8). Refuse to build if any fails.
2. New document `STF_Factory`. Build the white table, then the black ft base plates
   (Appendix B rects).
3. One module at a time, as nested `App::Part` containers **that ARE the joints**
   (HBW J1_Travel_X / J2_Lift_Z / J3_Ausleger_Y; VGR J_Swivel / J_Plunge / J_Reach;
   oven J_Ofenschieber / J_Ofentuer / J_Drehkranz / J_Sauger / J_Senken / J_Auswerfer;
   sorting J_Auswurf_weiss/rot/blau). The module placement is a rigid transform
   (Appendix B). Parts in module coordinates.
4. Replace every I/O part's primitive with the precise component
   (`stf-factory/cad/components/<id>.step` or `.FCStd`), placed by the `fit` block in
   `stf-hw/web/public/hbw_parts.json` (axis permutation + sign, det +1, real size, centred
   on the part envelope; see section 6).
5. PCBs, PLC cabinet, then wiring and hoses as swept tubes (`Part.Wire` + `makePipeShell`)
   from `hbw_parts.json` -> `wiring` (cables / bundles / power / hoses, colour per
   `wiring.roles`).
6. Save to `~/workspace/stf-factory/cad/STF_Factory_MCP.FCStd`, export STEP. Do not
   overwrite `STF_Factory.FCStd`, which is the headless build.

## 2. Source documents (in `~/stf/docs/hw`)

- `536634-Fabrik_Simulation_24V.pdf` (the booklet, 42 pp.):
  - p.3-6: Belegungsplan per module (Appendix E);
  - p.7: PLC I/O type (P-reading inputs, P-switching outputs);
  - p.8-11: Bauteilbeschreibung (component descriptions);

    - Abb. 5: 3/2-way solenoid valve (coil a, core b, spring c; ports 1 P, 2 A, 3 R);
    - Abb. 6: VGR kinematics;
    - Abb. 9: oven station areas;
    - Abb. 10: sorting line areas.
- `536634-Factory-simulation-24V-extended-description.pdf`: the 24 V adapter PCB and PLC
  interface (`controller.py` replicates it, 5 documented discrepancies).
- Datasheets:
  - 144643 encoder motor, 37783 mini switch, 36134 phototransistor, 128599 colour sensor;
  - RevPi Core / RevPi DIO (96 x 22.5 x 110.5 mm DIN housings);
  - Mean Well WDR (no dimensions printed);
  - occupancy plans (.ods) per module.

Facts from the booklet that shaped the model (do not re-derive):
- Process order (p.2): the VGR fills the HBW; the HBW stores by colour, then retrieves to
  the oven station; the processed pieces are sorted by colour into Lagerstellen; the VGR
  brings them back to the HBW. The workpieces START in the sorting Lagerstellen.
- **Oven station (p.30)**, in order:
  1. The VGR lays the workpiece on the extended Ofenschieber; light barrier I9 breaks.
  2. The door opens, the slider retracts, the piece is baked (Q9 lamp).
  3. The door opens and the slider extends; the station's **own** Sauggreifer puts the
     piece on the Drehtisch.
  4. The Drehtisch dwells under the Säge, then turns to the belt.
  5. The pneumatic Auswerfer pushes the piece onto the belt, which runs it through I3
     into the Sortierstrecke.
  6. Passing I3 sends the Drehtisch home, and the belt stops after a delay.
  - **No encoders** on the oven or the sorting line.
- **Sorting (p.35-36)**:
  - The colour sensor sends RED light and measures reflection; it is **NOT RGB**.
  - The inlet barrier starts the belt, and the piece passes a darkened lock (hood) with
    the sensor.
  - Two thresholds split white/red/blue. The I1 Impulstaster counts belt pulses so the
    ejector fires by distance, not time.
  - Bays nearest to farthest from the sensor are white, red, blue. Each bay has a barrier
    that can tell full from empty, but not how many pieces it holds.
- **Components (p.8-11)**:
  - Encoder motor: 24 V, 2.03 W at 214 rpm, 320 mA, 25:1, 3 pulses/motor-rev = 75/output-rev.
  - S-Motor: 24 V, max 300 mA, 5 mNm, 10 700 rpm, U-Getriebe 64.8:1 side output.
  - Compressor: 24 V, 0.7 bar, 70 mA, membrane pump.
  - Pneumatic cylinder: spring return; two coupled cylinders make the vacuum.
  - IR track sensor: 5-30 mm, 2 emitters + 2 receivers, push-pull, 9 V from the PCB.
  - Colour sensor: 0-9 V (booklet) vs 0-2 V (datasheet) vs 0-10 V (extended description).
    **MEASURE.**
  - 3/2 valve: energised 1 P -> 2 A, off 2 A -> 3 R; normally closed.
- Factory totals (extended description p.2): 26 DI, 10 counter, 1 AI, 35 outputs,
  24 V / 4.8 A.

## 3. Coordinate conventions (most bugs came from here)

- Every module is built and proven in its OWN frame, then placed by a rigid transform
  (it cannot introduce interference, so the module proofs carry over).
- **Factory frame:** the front edge of the table is x = 0 (+X runs to the back), "right"
  seen from the front is -Y, +Z up, mm.
- HBW, oven and sorting are rotated +90 deg about Z: module (x, y) -> factory
  (-y + TX, x + TY). The VGR and PLC are translated only.
- **Web viewer mirror bug (fixed):** three.js used v(x,y,z) = (x, z, y), a reflection, so
  the web twin drew the mirror image for its whole life. It is fixed with one
  scale(1,1,-1) group. FreeCAD/STEP/glTF were always right; no action is needed in
  FreeCAD.
- A moving thing's position must be DERIVED from the geometry that carries it, never a
  literal. A load in transit needs its own collision group.
- A FreeCAD document needs a ViewProvider for every object (containers too), a real
  camera, and hidden App::Origin planes, or the 3D view opens blank.

## 5. The modules (details in Appendix A, parts in Appendix G)

  - belt at x=665 with light barriers at both ends, a hood, toothed-belt drive;
  - 183 solids, `check()` 96 poses + `check_carry` + `check_path`.
- **VGR 536630** (`vgr_model.py`):

  - spring stem (6 mm) under the cup; cup radius 168..568;
  - `vgr_path.py` plans and sweeps the whole tour: belt -> oven tray -> rot bay -> belt,
    42 waypoints, ~2 200 swept poses.
- **Oven 536632** (`oven_model.py`, rebuilt to Abb. 9, then 2x):
  - ONE flow line x = 460: tray -> Sauger -> Drehtisch -> Auswerfer -> belt.
  - Q12 is a pneumatic cylinder with TWO positions, so tray top = disc top = belt top =
    Z_W 60, and ONE 50 mm stroke serves both Sauger stops (asserted).
  - Drehtisch stops: 0 Sauger, -90 Säge, -180 belt.
  - Interlocks proven: the slider moves only with the door open, Q12 lowers only at a
    stop, the Auswerfer fires only at the belt stop.
  - `check()`: 196 poses + the workpiece swept along its whole journey.
- **Sorting 536633** (`sorting_model.py`, mirrored to match the photos, then 2x):
  - belt +X, ejector cylinders BEHIND the belt pushing -Y, deep Lagerstellen in FRONT
    (factory: toward the VGR);
  - red hood (darkened lock) with the colour sensor 25 mm above the piece; I2 inlet,
    I3 after colour, I1 Impulstaster.
- **PLC cabinet** (`plc_model.py`):
  - DIN rail with WDR-120-24 PSU, RevPi Core 3, 3x RevPi DIO (14 in / 14 out each), and
    RevPi AIO (for A4); 12 feed terminals; a cable duct.
  - 36 DI+counter / 35 DO / 1 AI -> 3 DIO + AIO.
- **24 V adapter PCB** on every module:
  - 160 x 100 x 22 envelope (estimated): ST1/ST2 to the model, ST3 34-pin to the PLC,
    terminals 1-30, relays R1-R8, valve terminals V1-V4.
  - Bidirectional motors via relay pairs; both on = stop, not a short.

## 6. Precise components (`components.py` -> `components_cad.py`)

- Nine components are built as FreeCAD B-rep with sub-parts, checked to 0.01 mm against
  their table: encoder_motor 144643, mini_switch 37783, phototransistor 36134,
  colour_sensor 128599, s_motor, compressor, pneumatic_cylinder, ir_track_sensor 128598,
  solenoid_valve.
- Files: `~/workspace/stf-factory/cad/components/<id>.FCStd|.step` +
  `FREECAD_AI_PROMPTS.md`.
- Every dimension carries a source tag: datasheet / booklet / photo / ft-std / assumed
  (MEASURE). Only datasheet values justify a 0.1 mm claim; the booklet parts' sizes are
  all "assumed".
- Which model part IS which component: `parts_table._kind` (from the Belegungsplan).
  - Encoder motor only where B-channels are wired; every other motor is an S-Motor.
  - Light-barrier receivers are phototransistors; the transmitters are LEDs (not modelled).
  - The HBW's A1/A2 are ONE IR track sensor with 2 channels (the model draws two parts).
- **Fit** (`wiring.fit`): the component's overall bbox is laid into the part envelope by
  the axis permutation with the least error, det +1, at REAL size (never stretched),
  centred. The result is in `hbw_parts.json` as `fit {comp, perm, sign, centre, origin}`.
  FreeCAD placement: `Placement(centre) * Rotation(basis cols = sign_i * e_perm_i) *
  Placement(-origin)`.

## 7. Wiring (`wiring.py`, IEC colours)

- Colours: +24V red, 0V blue, PE green-yellow, mains L brown / N light blue, DI white,
  DO orange, ENC yellow, AI violet, AIR = translucent PU hose (not a wire).
- What each cable carries:
  - Sensor: +24V and DI.
  - LED transmitter: +24V and 0V.
  - Colour sensor: +24V, AI, 0V.
  - Actuator (valve, compressor, lamp, one-way motor): DO and 0V.
  - Bidirectional motor: DO and DO.
  - Pneumatic cylinders get HOSES from their valve, and the compressor feeds each valve.
- Routes lie on the table (z ~1.2), Manhattan with bend radius 10.
  - Each module PCB -> PLC duct: a bundle of single wires (every ST3 signal + 2x +24V +
    2x 0V).
  - In the cabinet: mains L/N/PE -> PSU; PSU -> terminals 1/4; PE -> DIN rail;
    terminals -> duct.
- Parts on moving frames are NOT wired yet (they would need drag chains): an open item.
